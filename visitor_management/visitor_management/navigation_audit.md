# Visitor Management Structural Navigation Audit

## Final Workspace Structure

The workspace now exposes one curated Visitor Management hub with these groups:

### Main Operations

1. `Visitor` — the single visitor list and form entry point. Today, Checked In, Checked Out, Pending, and This Month stay as cards/list filters, not duplicate menu pages.
2. `Scan QR` — the primary operational scanner entry point for check-in/check-out flow.
3. `Visitor Log` — access history and scan/approval audit trail.
4. `Visitor Appointment` — scheduled visitor appointments.
5. `Visitor Approval` — approval/rejection work queue.
6. `Visitor Blacklist` — blocked visitor registry.

### Masters

7. `Visitor Company` — reusable company master for Awesome Bar/list search.
8. `Visitor Purpose` — reusable visit-purpose master for Awesome Bar/list search.

### Settings

9. `Visitor Settings` — VMS visitor behavior settings.
10. `QR Settings` — VMS QR/scanner settings.
11. `Approval Settings` — VMS approval policy settings.
12. `Notification Settings` — the **Frappe core** Notification Settings route; Visitor Management no longer ships a DocType with this name.
13. `Gate Settings` — VMS gate/scanner defaults.

### Administration & Reports

14. `VMS Cleanup Tool` — dedicated cleanup page with preview, dry-run, selected delete, all-filtered delete, and background queue support.
15. `VMS Cleanup History` — readonly audit history generated by the cleanup tool.
16. `Visitor Reports` — report entry point for Visitor data.

Removed duplicate workspace menu concepts:

- Today Visitor / visitor duplicate pages.
- Separate Check In and Check Out pages; scanner resolves the correct action.
- Duplicate filtered report shortcuts.
- Duplicate Scan QR entries.
- `VMS Cleanup Log` as a user-creatable operational DocType.

## Cleanup Tool Design

`VMS Cleanup History` replaces the old `VMS Cleanup Log` design and is system-generated only:

- no manual create/import workflow;
- no manual write/delete workflow for non-system inserts;
- records are inserted only by `visitor_management.visitor_management.maintenance` with `frappe.flags.in_vms_cleanup`;
- human-readable filter fields replace raw JSON payload display;
- previous `VMS Cleanup Log` rows are copied forward by migration before the old DocType is removed.

The VMS Cleanup Tool page provides the enterprise workflow:

1. Select target DocType (`Visitor` or `Visitor Log`).
2. Apply filters (date range, older-than days, status, gate, company, visitor type, checked-out only).
3. Preview affected count and records.
4. Select rows for deletion or run all-filtered deletion.
5. Run dry-run mode to create an audit entry without deleting records.
6. Queue all-filtered deletion in a background job for large cleanups.
7. Review cleanup history in a readable table.

## Notification Settings Compatibility Notes

Visitor Management no longer ships any DocType, controller, fixture, or override named `Notification Settings` or `NotificationSettings`. VMS notification preferences live only in `VMS Notification Settings`, while the workspace `Notification Settings` shortcut intentionally routes to Frappe core.

The repair patch removes stale `Custom Field` and `Property Setter` rows that target Frappe core Notification Settings fields, reloads the core Frappe Notification Settings DocTypes, and provides last-resort v16 fallback metadata for `enabled` and `subscribed_documents`.
